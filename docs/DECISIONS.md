## ADR-002 実収支の数理モデル（役ごとの抽選＋出玉の対数正規分布）

- 日付: 2026-10-25 / 状態: 採用
- **背景**: 仕様は「実収支 = 期待値 + σ × 正規乱数」で、期待値どおりに勝てない下振れを厳密に再現すること。ただし設定判別には小役カウンターの数値が必要で、差枚と回数が矛盾してはいけない。
- **決定**:
  - 各役（BIG/REG/ブドウ/AT初当り等）の当選回数を二項分布 B(n, p) で引く。np>30 は正規近似、それ以下はポアソン近似
  - 1回あたりの出玉は「平均 x・標準偏差 s」の**対数正規分布**で引く。固定払い出しの役は s=0
  - 機械割と役の払い出しの差は「ベース（リプレイ等）」として自動補正し、長期の期待値が公表機械割に一致するようにする（`baseReturnPerGame`）
  - 合算すると中心極限で「差枚 ≒ 期待差枚 + σZ」になり、仕様の式を満たす
- **理由・却下案**:
  - 当初は出玉を正規分布で引いていたが、1回の当りで負の出玉が出て、スマスロの1日の最大負けが物理的な下限（約−259k円）を超えた（−335k円）。対数正規に変えて解決し、AT機らしい右に長い裾も得られた
  - 差枚を一発で `μ + σZ` と引く案は、小役カウンターと差枚が連動しなくなるため却下
- **検証結果**（1日7000G・各3000試行）: 全機種・設定1/6で、シミュレーションの平均と標準偏差が理論値と一致。σの目安はジャグラー系 ±27k円、組長2 ±47〜62k円、凱旋 ±86〜103k円、スマスロ ±94〜135k円
- **影響**: `src/engine/simulation.ts`

## ADR-003 非等価交換の扱い

- 日付: 2026-10-25 / 状態: 採用
- **決定**: 貸しは常に20円/枚（1000円＝50枚）。円収支 = 交換率 × 差枚 − 現金投資 × (1 − 交換率/20)。第2項を「交換ギャップ」とする
- **理由**: 非等価の本質である「現金投資するたびに価値が目減りする」を、期待値計算にもそのまま入れられる。持ちメダル遊技の優位性も自然に出る
- **影響**: `coinsToYen`（`src/engine/simulation.ts`）

## ADR-007 収支表には「推定期待値」を記帳し、真の値はゲームオーバー時に明かす

- 日付: 2026-10-25 / 状態: 採用（ユーザー承認済み）
- **背景**: 当初は真の設定から計算した期待値を記帳していたため、収支表から座った台の設定が逆算できてしまった。
- **決定**:
  - 設定狙いの日は、小役カウンターの事後確率（**一様事前分布**の二項尤度）で各設定の期待値・分散を重み付けした「推定期待値・推定σ・推定設定」を記帳する
  - 真の期待値と真の設定は `DayLog` に隠しフィールドとして持ち、ゲームオーバー時の「答え合わせ」でのみ表示する
  - ハイエナは天井・ゾーンの期待値が既知という扱いで、推定値＝真の値
- **意図的な偏り**: 一様事前分布のため、データが少ないほど高設定寄りに楽観的になる。特にスマスロは判別が効かず、設定1でも記帳上は+11k円（真の値は−13k円）になる。「帳簿上は勝っているのに、実際は負けている」状態を生むために、あえて採用している
- **影響**: `estimateFromCounters`、`DayLog`、`useLogStore` の v2 マイグレーション

## ADR-009 UI は SPA ダッシュボードをやめ、ドット絵＋選択肢のゲーム画面にする

- **却下案**: Canvas 描画（クリック判定とテキストが扱いにくい）、画像アセットのドット絵（現段階では量産しにくい）

## ADR-010 ローグライク要素：出自・突発イベント・パーマデス・墓標

- 日付: 2026-10-26 / 状態: 採用（ユーザー指示「ローグライクシミュレーション」）
- **決定**:
  - **出自**: 人生ごとに6種からランダムに3つ提示し、1つ選ぶ。初期資金・体力・精神・社会信用と、毎月の収支（仕送り+5万／借金返済−3万）が変わる
  - **突発イベント**: 毎朝14%の確率で（週単位化に伴い「週の初めに40%」に変更。ADR-013）、条件を満たすイベントから重み付きで1つ発生し、選択肢で結果が変わる（母の電話、結婚式、確定申告、腰痛、店長、軍団の打ち子勧誘、元同僚、孤独、父の入院、求人チラシ）。`once` のイベントは1回の人生で一度だけ
  - **パーマデス**: 資金<0、体力0、精神0、2026年末到達、または求人チラシで「足を洗う」を選ぶと、その人生は終わる
  - **墓標**: 終わった人生の記録（出自、最期の日、記帳EV、真のEV、実収支、最期の理由）を `useRunStore` に残し、人生をまたいで保持する
- **理由**: 1回の人生の中で同じ判断を繰り返すだけでなく、「次の人生では違う生き方をする」動機を作るため
- **影響**: `src/data/{traits,events}.ts`、`src/stores/{useGameStore,useRunStore}.ts`、`Phase` に `TITLE` を追加

## ADR-013 1ターン＝1週間（方針決め＋おまかせ稼働＋勝負日）

- 日付: 2026-11-21 / 状態: 採用（ユーザー指示「結構長い？」→ 提案を承認）
- **背景**: 1日＝1ターンでは2008〜2026年で約6,800ターンあり、1日30秒でも約57時間かかる。ローグライクの1周として長すぎた。
- **決定**:
  - 週の初めに「暮らし方（自炊／コンビニ／銭湯）・通う店・打ち方（設定狙い／ハイエナ）・稼働日数（週5〜7）・勝負日」を選ぶ。2週目からは「先週と同じ方針で」を選べば勝負日の選択だけで済む
  - 勝負日以外は `autoDay` が自動で消化し、毎日1行ずつ収支表に記帳する（リアルさは落とさない）
  - 勝負日だけは、抽選・台選び・続行／ヤメの判断を手動で行う。勝負日の候補は今週の各店の狙い日と「週末にいつもの店で」。作らなければ全日おまかせ
  - 週の締めに週報（稼働日数・推定期待値・実収支・乖離・プレミアや確定演出の記録・月初の引き落とし）を見て眠る。「求人サイトを眺めてから眠る」はここに移した
  - 突発イベントは週の初めに40%で判定（1日14%から変更）
  - 休む曜日の優先順は日・水・木・火・月・金・土。勝負日は休みにしない
- **却下案**: 1ターン＝1ヶ月（判断の機会が少なすぎ、時代の変化を実感しにくい）
- **結果**: 自動シミュレーションでは、1周はおよそ50〜300週（ターン）。2026年到達は非常に難しい
- **影響**: `src/stores/useGameStore.ts`（`planWeek` / `finishShoubu` / `nextWeek`）、`src/engine/autoplay.ts`、`src/components/phases/{WeekPlan,ShoubuNight,WeekEnd}Phase.tsx`。旧 `Morning/NightPhase` と夜の行動の選択は削除

## ADR-014 機種拡充・プレミアフラグ・確定演出・偽物示唆

- 日付: 2026-11-21 / 状態: 採用（ユーザー指示「マンネリしそう。プレミア、ブラックアウト、フリーズ、6確、偽物示唆も入れたい」）
- **決定**:
  - 機種を7種から18種にし、どの時代にも6〜9機種が並ぶようにした（5号機黎明・5号機ART全盛・6号機・スマスロ）
  - 役に種類（`kind`）を持たせる。`NORMAL`＝通常の役、`HINT`＝設定示唆・確定演出（出玉なし）、`PREMIUM`＝フリーズ等（大量出玉）
  - **確定演出**は「その設定では出現しない」＝分母 `Infinity` で表す。判別ツールの尤度計算で該当設定が自動的に否定される（`binomialLogLik` で p=0 を扱う）。6確が出た日は記帳する推定期待値も正確になる
  - **偽物示唆**は `published: false`（解析で確率が判明していない「噂」）で表す。意味ありげな文言（「高設定の証（常連談）」など）だが、設定差はほぼない。自作の判別ツールには入らず、プレイヤーの判断だけを惑わせる。「設定2以上濃厚」のような、本物だが弱い示唆も混ぜて過大評価を誘う
  - **演出**は派手にしない。フリーズ・暗転は画面が真っ黒になり文字だけが出る。確定演出は画面が暗くなり「設定6確定」とだけ出る。「閉店まで回す」はプレミア・確定演出を引いた時点で止まって見せる
  - ジャグラー系は、実機どおり示唆もプレミアもない「ブドウを数えるだけ」の機種として残す
- **検証**: 18機種すべてで、モンテカルロの平均・標準偏差が理論値と一致（1日7000G・1500試行）。6確を引けば事後確率が設定6に100%、噂だけでは判別が動かないことも確認
- **影響**: `src/data/machines.ts`、`src/types`（`FlagKind` / `PremiumStyle`）、`settingPosterior`、`src/components/phases/PlayPhase.tsx`

## ADR-015 物価のインフレ（生活費の上昇）

- 日付: 2026-11-21 / 状態: 採用（ユーザー承認）
- **背景**: 「インフレしていく感じもあり？」という提案に対し、RPG的な自己強化ではなく、現実に起きた物価上昇で表現することにした。
- **決定**:
  - 環境に物価指数（2008年=1.00）と月の固定費を追加し、ニュースで段階的に上げる。2014-04 消費税8%（1.04／9.8万）、2019-10 消費税10%（1.07／10.1万）、2022-04 値上げラッシュ（1.12／10.6万）、2024-07 新紙幣（1.18／11.2万）、2025-05 米価高騰（1.26／11.8万）
  - 日々の暮らしの費用は「2008年の額 × 物価指数」
  - 貸メダルは20円/枚のまま。「出ていく金は増え、入ってくる金は規制と軍団で細る」構図にする
  - 荒さ（σ）のインフレは既存の機種スペックで表現済み（5号機ジャグラー ±27k → スマスロ ±130〜150k）
- **影響**: `src/data/eras.ts`、`Environment`、`lifestyleCost`

## ADR-016 前世の記憶（人生をまたぐ引き継ぎ）

- 日付: 2026-11-21 / 状態: 採用（ユーザー指示「引き継ぎ要素もあり」）。「店の癖」は ADR-018 に合わせて「強い日・入れ方・告知の正直さが分かる」（記憶3）に変更
- **決定**:
  - 人生が終わると記憶ポイントを得る。1 + 生き延びた半年ごとに1 + 2026年末到達で3

- **理由**: リアルさを崩さないよう、効果は「知識（見えるものが増える）」と「小さな下駄」に留める。強さのインフレにはしない

## ADR-017 おまかせ稼働の判断ロジックとバランス再調整

- 日付: 2026-11-21 / 状態: 一部廃止（ハイエナの値・店の甘さ・昭和通りは ADR-023 で置換）
- **背景**: 週単位化後に人生を自動で最後まで回したところ、次のことが分かった。
  - ハイエナ中心が3回とも2026年まで生き残り、生涯+4,800万円になった。時給2,400円相当を1日12時間ずっと拾える計算になっていた
  - 一方、ハイエナを修正すると、設定狙いはどの店でも1年以内に破産した。おまかせの台選び・見切りが下手だった（以前生き延びていたのは、台が取れずにハイエナに回った日の稼ぎのおかげだった）
- **決定**:
  - ハイエナの期待値は「拾える台がない時間も含めた1日平均」に変更。45枚/時（2008）→30（5.9号機）→22（6号機）→15（スマスロ）→9（軍団・SNS期）
  - 店マークの効きを強化。期待値に掛かる係数を `1 − mark/200` から `max(0.2, 1 − mark/125)` に変更
  - パーラー昭和通りを「たまに当たる穴場」に調整（設定4以上が14%→20%）
  - おまかせの見切りは「その店の普段の設定配分」を事前分布にした判別で行う（専業は店の傾向を知っている）。**記帳する推定期待値は一様事前分布のまま**（ADR-007 は維持）
  - 見切ったら帰らずに別の空き台へ移る（1日最大3台）。台選びは前日のボーナス合算の良さで重み付けする
- **結果**（各3回）: 昭和通り・設定狙いで約1〜2.5年、エスペランサ・ハイエナで最長約6年（2014年に破産）。所持金の少ない出自は数週〜2年。手動の勝負日と前世の記憶で延命する余地を残している
- **影響**: `src/engine/autoplay.ts`、`src/engine/session.ts`、`src/data/{eras,parlors}.ts`、`settingPosterior`（`prior` 引数）

## ADR-018 店の癖・告知（店からの示唆）・並び・全台系を推理するゲームにする

- 日付: 2026-11-26 / 状態: 一部廃止（データサイトは ADR-025 で有料会員制に変更）。採用（ユーザー指示「面白さに欠ける」→ 提案Aを承認。「店のくせに加えて、店からの示唆や並び、全台系なども考慮できるように」）
- **背景**: 判断が浅く（毎週同じ方針を押すだけ）、収支表が次の判断に役立たず、何周しても同じ世界だった。実際の専業の腕の差は「店の癖を見抜けるか」にある。
- **決定**:
  - **店は人生ごとにランダム生成**（大型2・中型2・小型2の6軒）。隠れた癖を持つ：強い日（末尾の日／ゾロ目／曜日／月初／なし）、入れ方（全台系／並び／末尾／角台／バラ）、据え置き率、凹み上げ、告知の正直さ、軍団との癒着
  - **島の機種構成は四半期ごとに固定**（「#115はハーデス」と覚えられる）。機種の塊の両端を角台とする
  - **設定の決め方**：前日据え置き → 強い日の入れ方 → 通常日の散らし → 凹み上げ。強い日の具体的な入れ方（どの機種・どの並び）は日付から決まるので、告知と実際の設定が食い違わない
  - **告知・匂わせ**：強い日は（正直な店なら）本当の入れ方を、嘘つきの店は別の入れ方を言う。強くない日にも煽るだけの店がある。媒体は時代で変わる（〜2011/6 店内告知で明言、以降はブログ→Twitter→X の匂わせ、2014〜は取材）。告知が出た日は嘘でも並びが2.5倍になる
  - **一般客も告知を読む**：告知に合う台に4倍の重みで座る。軍団（癒着店では+30%）は高設定を先取りする。だから「みんなが読む告知」だけでは勝てず、無告知の強い日・嘘つき店の見抜き・並びの発見が差になる
  - **推理の材料**：閉店後データを店ごとに21日分保存（`useShopDataStore`）。2015年以降はデータサイトの時代として、行かなかった店のデータも毎日残る。PCの「店のデータ」（全台のG数・ボーナス・差枚に条件付き書式）と「店舗別」（日付の末尾別・ゾロ目・曜日別の平均差枚）で癖を探す
  - **おまかせの狙い方**：週の方針で「告知どおり／前日好調台（据え置き狙い）／前日凹み台（凹み上げ狙い）／角台／末尾＝日付」を選ぶ。告知が出た日は、その店へ行って告知どおりに座る
- **検証**: 強い日でも空いている高設定は2〜5台残る。最善の空き台に座れば+1.8〜5.5万円/日、適当に座ると−0.9〜+0.0万円/日。癖に合った狙い方を選ぶと平日の真EVが ±0〜+5k/日、合わないと −1〜−2.5k/日
- **却下案**: 固定の3軒に癖を足す（何周しても同じ答えになりローグライクにならない）
- **影響**: `src/data/parlors.ts`、`src/engine/floor.ts`（全面書き換え）、`src/engine/autoplay.ts`、`src/stores/useShopDataStore.ts`、`src/components/pc/ShopSheets.tsx`、`WeekPlanPhase`

## ADR-025 買い物（道具・情報・会員）と人を雇う（引き子・打ち子）

- 日付: 2026-11-25 / 状態: 採用（ユーザー指示「所持金で便利になるアイテムを買えるようにしたい。恒久的なものと消費的なもので、実際にあるものに準えて」。例としてデータロボサイトセブン、カチカチくん、有料note、打ち子・引き子（持ち逃げリスクあり））
- **決定**:
  - 週の締めに「道具・情報を買う」「人を雇う」を追加。種類は3つ：**恒久**（一度買えばずっと）、**会員**（月初に会費、解約可）、**消費**（その場で効く／一定期間だけ効く）
  - 名前は ADR-005 と同じくパロディ（「データロボ サイトナナ」など）。物の値段には物価指数が掛かる。ネットの会費・noteは据え置き
  - **小役カウンター**（恒久・1,980円）：持っていないと、ブドウ等の小役（データカウンターに出ない役）を判別に使えない。手元のメモに「数えていない」と出て、判別メモ・おまかせの見切り・記帳の推定期待値がボーナス回数と示唆だけになる。**新しい人生は持っていない状態で始まる**
  - **ゲルクッション**（恒久）体力の削れ−2/日、**ノイズキャンセリングイヤホン**（2019-10-30〜）精神の削れ−1/日
  - **データサイト有料会員**（2015-01-01〜・月額330円）：ADR-018 では2015年以降は誰でも全店のデータが残ったが、**会員だけ**に変更。2015-01 にニュースで知らせる
  - **攻略誌**（4週間・ハイエナ期待値+10%）、**有料note／有料メルマガ「天井・ゾーン狙い目」**（8週間・+30%、ただし3割は中身が薄く+5%）。noteは2014-04-07（サービス開始）以降の名前で、それ以前は有料メルマガ
  - **有料note「地域ホール傾向」**：1店の強い日・入れ方などが分かる（週の方針の店選びに表示）。**3割は入れ方が外れている**ので、データで確かめる必要がある
  - **栄養ドリンク**：その場で体力+6・精神+1
  - **引き子・打ち子は勝負日にだけ連れていく**。引き子（日当2,000円）は一緒に抽選を引き、いちばん若い番号を自分が使う。打ち子（軍資金5万円を預ける、日当3,000円＋勝った日は勝ち分の3割）は自分の次に若い番号で入り、**自分が指示した台**を「閉店まで打ち切る」か「見切ったら帰る」。収支は自分の記帳にまとめ、日当・歩合は週報の「人件費」に出す。連れて打つと店マーク+3
  - **持ち逃げ**：勝負日ごとに 3% ×（1 − 律儀さ）、勝ち分が3万円を超えた日は4倍（ADR-026 で 2%・3倍に変更）。律儀さは雇ったときに 0.2〜1.0 で決まり、見えない。持ち逃げされると軍資金とその日の出玉を失い、精神−8。現金が尽きたら軍資金を引き上げて解散する
- **理由・却下した代替案**:
  - 打ち子を「おまかせ稼働の毎日、同じ狙い方で打たせる」案は、実装して測ったうえで却下。おまかせの設定狙いは平均でマイナス（ADR-023）なので、日当7,000円では必ず赤字になり、引き子もおまかせの日は逆効果だった（台が取れずハイエナに回る方が期待値が高い）。実際の軍団も、イベント日に頭が台を割り振る形で動いている
  - 日当だけ（7,000円）の案は、最善の空き台に打たせても赤字だった（打ち子の番号の時点で高設定の空き台が残るのは約2割）。日当＋歩合にして、勝たせた分だけ払う形にした
  - 小役カウンターを最初から持たせる案は却下。ユーザーの例（買うと設定狙いの精度が上がる）に合わせ、最初の買い物として機能させる
- **検証**（勝負日、引き子1・打ち子2、2008・2012・2019年の告知日）:
  - 打ち子を最善の台（設定4以上が空いていれば閉店まで、なければ帰す）に割り振ると、打ち子の真EVは人件費を引いて約+2,800円/日。引き子で自分の台も良くなり、自分の真EVは引き子なしより約+1万円/日
  - いつもの狙い方に任せると、打ち子は人件費込みで約−12,800円/日。**店を読めないと打ち子は赤字**
  - 持ち逃げは打ち子1人の勝負日あたり約1%
  - 人生の自動シミュレーション（勝負日なし）の生存期間は 1〜2年で、ADR-023 から変わらない。おまかせ稼働では、小役カウンターの有無による期待値の差は誤差の範囲（見切りの事前分布が強いため）。カウンターが効くのは主に勝負日の自分の判断
- **影響**: `src/data/items.ts`、`src/types`（`Inventory` / `Crew` / `Runner` / `RunnerShift` / `Gear` / `Today.lotteries` / `Today.runnerShifts` / `WeekSummary.crewCost`）、`settingPosterior` / `estimateFromCounters` / `makeLog`（`handCounter`）、`advanceSession`（`hyenaBoost`）、`dayStrain`（`gear`）、`floor.ts`（`drawLotteryNumbers` / `takeUnitsBetween`）、`autoplay.ts`（`runnerPlay`）、`useGameStore`（v5、`buyItem` / `hireRunner` / `assignRunner` ほか）、`WeekEndPhase` / `FloorPhase` / `PlayPhase` / `WeekPlanPhase` / `ShopSheets`

## ADR-026 見切ったあとのハイエナ（打ち子・自分）

- 日付: 2026-11-25 / 状態: 採用（ユーザー指示「打ち子に途中からハイエナさせたい。設定を見切ったあと自分もハイエナできるようにしたい」）
- **決定**:
  - 打ち子への指示を3つにする：閉店まで打ち切る／**見切ったらハイエナに回す**／見切ったら帰る。台を渡さずに「最初からハイエナで巡回させる」もできる。「いつもの狙い方に任せる」は見切ったらハイエナ
  - 打ち子のハイエナは自分の店マークを使わない（顔を知られていない）。攻略誌・有料noteの効き目は打ち子にも効く（教えている）
  - 勝負日の自分も「見切ってハイエナに切り替える」を選べる。台を立つと、その時点のデータを残して空き台になる（台移動と同じ）。記帳は台移動と同じく1行にまとめる
  - 持ち逃げの確率を 3%×（1−律儀さ）×大勝ち日4倍 から **2%×（1−律儀さ）×大勝ち日3倍** に下げた。高設定を打たせるほど大勝ち日が増え、上手く割り振るほど約5%/回で持ち逃げされる不自然さがあったため（変更後は約0.7%/回）
- **検証**（勝負日300回、引き子1・打ち子2）: 打ち子1人あたりの真EVは、任せて見切ったら帰る −2,100円、任せて見切ったらハイエナ −1,700円、最初からハイエナ +3,000円（人件費込みでは赤字）、高設定が空いていれば打ち切り・なければハイエナ +8,600円。ハイエナだけで打ち子を回して稼ぐ抜け道はない
- **影響**: `RunnerOrder`、`RunnerShift.order`、`runnerPlay`（`order` / `hyenaBoost`）、`useGameStore`（`assignRunner` / `switchToHyena`）、`FloorPhase`、`PlayPhase`

## 保留中の論点・次にやること

- 環境音（自室の雨音・冷蔵庫、ホールの騒音）は未実装。効果音のみ（ADR-020）
- 技術介入（ビタ押し）のミニゲームは未実装。現在は技術介入100%の機械割で固定
- 出禁（店マーク100）の仕組みがない。今は店長イベントで間接的に表現しているだけ
- バランス（ADR-023）は自動シミュレーションでの暫定値。人間が勝負日に癖を読んだときの勝ちやすさは、実際に遊んで確かめる必要がある
- 死因のほとんどが破産。体力・精神で終わることはまれ
- 所持金の少ない出自（大学中退・仕送り）は数週で終わることがある
- おまかせ稼働の記帳EVは真のEVより楽観的に出る（ADR-007 の意図どおりだが、乖離の大きさは要検討）
- ハイエナは期待値が既知という簡略モデル。台ごとの天井・ゾーンのシミュレーションにするかは未定
- 開店時に誰も座らなかった台は、終日データが0のまま（実際は昼から一般客が座る）
- 店のデータは店ごとに21日分しか残らない（セーブ容量のため）。長期の傾向を見る手段がない
- 買い物（ADR-025）のバランスは、人間が勝負日に打ち子を割り振ったときの勝ちやすさを、実際に遊んで確かめる必要がある
- 打ち子は勝負日にしか使えない。おまかせの日に告知店へ送る運用（軍団的な毎日の稼働）は未実装
- 引き子・打ち子を連れても、抽選の並びの絵（人数）は変わらない
